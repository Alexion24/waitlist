# Будьте в числе первых

Лендинг собирает email в список ожидания. Когда основной сайт открывается, подписчики получают письмо со ссылкой, а на лендинге вместо формы появляется кнопка перехода.

## Быстрый старт

Нужен Node.js 24 или новее. Проверьте версию командой `node --version`. Все зависимости входят в Node.js.

Если у вас ещё нет копии проекта, скачайте её через Git:

```powershell
git clone https://github.com/Alexion24/waitlist.git
cd waitlist
```

Из папки проекта запустите сервер:

```powershell
node app.js
```

Откройте [http://127.0.0.1:3000/](http://127.0.0.1:3000/). Оставьте терминал открытым, пока пользуетесь сайтом. Чтобы остановить сервер, нажмите `Ctrl+C`. Адреса сохраняются между перезапусками в `.data/waitlist.sqlite`.

Если порт 3000 занят, выполните в PowerShell `$env:PORT = '3001'` и снова запустите `node app.js`. Откройте адрес, который сервер напечатает в строке `Local:`.

## Проверка записи и рассылки

Для теста используйте отдельную базу, поскольку запуск закрывает запись в ней. Остановите сервер, если он уже работает, и запустите его из папки проекта:

```powershell
$env:WAITLIST_DATA_DIR = Join-Path $PWD '.data/demo-01'
node app.js
```

1. Откройте лендинг и введите `visitor@example.test`. Должно появиться сообщение «Вы в списке!».
2. Во втором терминале откройте ту же папку проекта и выполните:

   ```powershell
   $env:WAITLIST_DATA_DIR = Join-Path $PWD '.data/demo-01'
   Remove-Item Env:RESEND_API_KEY, Env:EMAIL_FROM -ErrorAction SilentlyContinue
   node app.js launch https://example.com
   ```

3. Откройте файл `.eml` в `.data/demo-01/outbox/` и проверьте адрес и ссылку. Это тестовое письмо, сохранённое на диск.
4. Обновите лендинг. Должен появиться заголовок «Мы открылись!» и кнопка перехода. Повтор той же команды покажет `Saved to outbox: 0`. Для нового прогона выберите свежую папку, например `.data/demo-02`, в обоих терминалах.

## Публикация и реальная рассылка

1. Запустите лендинг как процесс Node.js на сервере и направьте HTTPS-трафик на него через обратный прокси. Сейчас приложение слушает только `127.0.0.1`. Для SQLite выделите постоянный каталог и передайте его путь в `WAITLIST_DATA_DIR`.
2. Настройте `RESEND_API_KEY` и `EMAIL_FROM` в окружении команды запуска или в локальном файле `.env`. В `EMAIL_FROM` укажите адрес с [подтверждённого домена в Resend](https://resend.com/docs/dashboard/domains/introduction).
3. Настройте процесс публикации основного сайта так, чтобы после проверки доступности он выполнил команду ниже с настоящим URL. Команда должна работать с тем же каталогом SQLite, что и лендинг.

   ```powershell
   node --env-file-if-exists=.env app.js launch https://example.com
   ```

Команда автоматически отправит письма всем записавшимся. При ошибке повторите её с прежним URL и настройками. Она обработает только адреса без отметки об отправке. Если ответ от сервиса потерялся, повторите команду в пределах [24-часового окна Resend](https://resend.com/docs/dashboard/emails/idempotency-keys).
